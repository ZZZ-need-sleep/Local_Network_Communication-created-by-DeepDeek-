## 一、简体中文

### 1.1 项目简介

内部网 局域网群组（简称「班群助手」）是一个局域网群组软件，提供 **Python 版** 与 **C++ 原生版** 两个同等级实现：

- **两版都零第三方依赖**：Python 版只用 `socket / threading / tkinter / hashlib / hmac / json / urllib / subprocess` 等标准库；C++ 版只用 Windows 自带的 Win32 + GDI+，编译出一个单文件 `neiwang.exe`；
- **C++ 版不需要装 Python**：把 exe 复制过去双击就能用，适合不想在每台电脑上装运行环境的班级（详见 1.4 节）；
- **无需服务器**：没有中心服务端，所有电脑平等互联，谁先建群谁就是群主电脑，其他人凭群号加入；
- **先入网再用**：局域网里的电脑先组成一个「**内网**」（登记每台电脑的物理地址，人多时新成员需成员投票通过），
  没入网的电脑程序是空的——群组、聊天、文件都用不了；
- **界面仿微信 4.x 桌面版**：左侧窄图标栏（聊天 / 内网 / 投票 / 更多 / 日志）+ 中间群组列表（搜索、未读红点、右键菜单）+ 右侧聊天气泡主区（微信绿、圆形头像、群文件、成员列表）；
- **面向班级场景**：作业互传、通知广播、临时聊天，局域网内不需要外网也能用。

### 1.4 C++ 原生版（新）

除了 Python 版，本项目还提供一套**完全独立的 C++ 原生版**：纯 Win32 + GDI+ 手绘界面，零第三方依赖，
编译出来就是一个单文件 `neiwang.exe`。两版**同等级、功能对齐**，可以只选一种，也可以混着用。

- **为什么有 C++ 版**：不用在每台电脑上安装 Python 与 tkinter；单文件 exe 复制即用、启动快、不残留黑色控制台窗口；
  适合机房 / 教室那种不方便逐台装环境的场景。
- **协议完全兼容**：网络报文、端口（UDP 45455 / TCP 45431）、数据文件格式与 Python 版完全一致，
  **两版可以在同一个内网、同一个群里互相收发消息与文件**（有的电脑用 Python 版、有的用 C++ 版都没问题）。
- **如何构建**：安装 Visual Studio 2022 生成工具（勾选「使用 C++ 的桌面开发」工作负载，并带 Windows SDK）后，
  双击 **`构建C++版.bat`**（内部调用 `cpp\build.bat all`），或在命令行执行 `cpp\build.bat all`；
  产物在 **`cpp\build\`**：`neiwang.exe`、`neiwang_update1.exe`、`neiwang_update2.exe` 与测试用的 `test_*.exe`。
- **如何运行**：双击 **`启动C++版.bat`**（若还没构建过会自动先构建），或直接运行 `cpp\build\neiwang.exe`；
  数据目录与 Python 版一样是程序目录下的 `data/`，开箱即用。
- **如何更新**：双击 **`更新C++版.bat`**（等价于运行 `neiwang_update1.exe`，它再驱动 `neiwang_update2.exe`，见 1.12 节）。
- **与 Python 版的差异**：界面是 Win32 自绘（外观与 Python 版一致：圆角、微信绿、同样的三栏布局）；
  数据目录 `data/` 的结构完全相同，把 `data/` 从一版搬到另一版可以直接接着用。

> 只想要一个能跑的程序：装了 Python 就用 Python 版，不想装环境就用 C++ 版；两版混用也完全没问题。

### 1.5 内网准入与入网投票（新）

程序把同一个局域网里的电脑组成一个「**内网**」：**没被接纳的电脑，程序就是空的**（群组、聊天、文件都用不了）。
每台电脑的**物理地址（MAC）**会登记在内网成员表里，登记表全网同步、人人可见。

**启动时自动做的事**：

1. 已经在内网里 → 直接广播自己的内网（带上物理地址与成员表）；
2. 还没有内网 → 先**扫描**附近的内网（局域网 IP）：
   - **扫描到** → 自动**申请加入**（内网人数超过 5 人时进入投票，规则见下）；
   - **没扫描到** → **自行建立**一个内网，自己成为发起者。

**入网投票门槛**（按约定规则）：

| 内网现有成员 | 新成员加入需要 |
| --- | --- |
| **≤ 5 人** | 免投票，自动通过 |
| **6 – 7 人** | **全票通过**（每位成员都要同意） |
| **≥ 8 人** | 同意票**超过 1/3**（8 人需 3 票、9 人需 4 票、12 人需 5 票；1/3 规则不得少于 8 人） |

**投票怎么进行**：

- 所有入网申请**统一收在左侧「投票」图标**里：有待投票时图标出现**小红点**；
- **鼠标靠近图标才弹出面板**（不会自动弹窗打扰人），点图标进入完整投票页；
- 每项可选 **同意 / 拒绝 / 弃权**（弃权既不算同意、也不算反对）；
- 投完后小红点消失；**投出后 5 分钟内可以改票**，超过 5 分钟锁定；
- **一次投票有效期为 1 天**，超过 1 天视为投票结束（票数不够则申请失败，可重新申请）；
- 投票历史在左侧「**更多**」页里查看（5 分钟内且投票未结束的，可在那里改票）；
- **没有「自动同意」开关**：必须由人点，机器不会替用户同意。

**其它细节**：

- 成员表记录：名字、**物理地址**、内网 IP、加入时间、角色（发起者 / 成员）；
- 离线的成员仍算成员：投票有效期内上线后照样能投（申请会持续重播，登记表会把待办投票同步给刚上线的电脑）；
- **公共日志**里能看到「某某（物理地址 XX-XX-…）申请加入内网」的完整过程；
- 手动**退出内网**后不会自动加回去（可在「内网」页手动申请其它内网或自行建立）；
  退出会把自己从登记表移除，再想进来需要重新投票；
- 发起者可在「内网」页**重命名**自己的内网。

> 取不到网卡 MAC 的机器（例如部分虚拟机）会自动生成一个持久随机 ID 当物理地址用
> （显示成 `RND-XXXX-XXXX-XXXX`），同样会被登记、同样参与投票。

### 1.6 快速开始

> **首次启动会自动组网**：程序扫描附近的内网——找到就申请加入（人多时需要成员投票），
> 找不到就自己建一个；**加入内网之后**才会出现群组功能（详见 1.5 节）。

1. 每台电脑安装 **Python 3.8+**（Windows 安装时记得勾选 *Add Python to PATH*）；**不想装 Python 就直接用 C++ 版**（见 1.4 节）。
2. 把整个文件夹复制到每台电脑（U 盘 / 网盘 / 共享文件夹都行，不需要放到同一路径）。
3. Windows 双击 **`启动.bat`**；其他系统命令行运行 `python neiwang.py`。C++ 版则是双击 **`启动C++版.bat`**（或运行 `cpp\build\neiwang.exe`）。
4. **创建群**：点「＋ 创建群组」输入群名（如：高三（2）班），程序自动生成 **6 位群号**。
5. **加群**：其他同学点「加入群组」→ 自动扫描局域网里发现的群 → 选中加入；也可以手动输入群号。
6. **改名**：点左下角头像（或「设置」）→ 输入新名字。**第一次改名直接生效**；之后的修改会发起投票。
7. **聊天**：选中群组 → 打字回车发送。
8. **私聊**：群内切到「成员」页 → 点某位同学头像（或直接点聊天里对方的头像）→ 弹出私聊窗口。
9. **发文件**：点「📎 发送文件」→ 选文件 → 全组成员自动下载 → 完成后弹系统通知。
10. **看文件**：切到「群文件」页，双击文件即可用系统默认程序打开。

> 建议：群号告诉大家，由一台电脑创建群组即可，所有加入者共享同一个群。

### 1.7 改名投票规则

- **第一次改名**：在「设置」里直接保存，立即生效，不需要任何人同意。
- **第二次及以后**：点「保存名字」会向局域网广播投票请求，其他在线用户弹出
  「某某申请把名字从 A 改为 B，是否同意？」→ 点「同意 / 拒绝」。
- **生效条件**：收到**超过 5 名用户**的同意票（默认值，可在 `data/config.json` 的
  `rename_vote_need` 修改）；**120 秒**内票数不足则失败，可以重新发起。
- **防刷票**：同一台电脑对同一次投票只计一票；每次投票都有唯一编号，互不干扰。
- 申请与通过结果都会写入公共日志，全员可见。

### 1.8 双人私聊与离线保密转存

**私聊入口**：群「成员」页点成员头像，或聊天区点对方头像 / 名字。

**在线时**：消息定向发送，只有收件人收到，其他人不显示、不记日志。

**对方离线时（保密转存）**，过程完全自动：

1. 你的程序把消息用**随机密钥加密**（每条消息一把新密钥），转存给某位在线的同学 C；
2. **C 全程无感**：没有弹窗、没有日志、界面上看不到，磁盘里只有密文；
3. 对方 B 一上线（心跳广播），C 的程序自动把密文包直连送达给 B；
4. B 解密并做 **HMAC 完整性校验**，完整才回执；C 收到回执后**删除**转存内容；
   校验失败则保留重试（最多 3 次）；
5. B 的界面像普通私聊一样显示，并带「离线转存送达」标记。

> 说明：转存使用纯标准库流加密 + HMAC 做「机器级」保密与完整性校验（转存方用户无法在应用里查看）。
> 如需抵抗「转存方直接翻磁盘」的更强保密，可升级为非对称加密。

### 1.9 群文件分发策略

1. **发送人在线** → 接收者直接向发送人电脑**点对点下载**（SHA-256 校验，损坏自动重试）。
2. **发送人离线** → 在「日志」里**公共询问**（全网可见、人人可看不可操作）：
   其他下载过该文件的电脑自动返回自己的局域网 IP（没下载过则无应答），
   请求方自动向**第一个返回的 IP** 请求文件，全程无需两端用户操作。
3. 加入群组时会自动同步该群文件列表，错过的文件会自动补下载。

### 1.10 局域网活动历史（新）

程序会把局域网里发生过的活动（公共日志、群聊、代理操作、系统 / 上线提醒）持久化成本机的
**局域网活动历史**（`data/active_log.json`），并让设备之间互相补齐——**关机、断网期间错过的信息不会丢**。

**空设备启动提示**：

- 「设备空有程序、没有任何局域网相关数据」时（没入内网、没有活动历史、还没有任何群组），
  启动后会弹出对话框：标题 `内部网`、正文 **「当前没有局域网网络活动，是否新建？」**，
  说明行「未发现局域网内已有的内网与活动数据，你可以新建一个内网并创建第一个群组。」；
- 按钮是 **`是，新建（推荐）`** 与 **`否，稍后`**：选「是」→ 新建内网（扫描到附近的内网则先申请加入）并打开「新建群组」，
  日志写「本机没有局域网活动数据，已按用户选择新建内网「…」」；选「否」→ 只写一条日志「当前没有局域网网络活动（未新建）」；
- **本机已经有活动数据时不弹这个提示**，改为走下面的自动补齐流程。

**有数据时启动会自动补齐**：

- 启动时（之后每 60 秒一次）向局域网广播自己的**物理地址 + 本机 IP + 最后一次数据获取时间**、
  活动条数、本进程连续运行起始时间与内网号；
- 内网里的其他设备收到后**立刻回应校验数据**（同样带物理地址、连续运行时间、最后数据时间、条数与校验指纹），
  日志会逐条记下：「收到「设备二」（物理地址 11-22-33-44-55-66）的局域网活动校验数据：连续运行自 …，最后数据 …，共 N 条」；
- 请求方在 **6 秒**窗口内挑出**合格应答**：对方必须是「从我的最后数据时间之前就一直运行」，
  并且在这些合格者中选**最先到达（响应最快）**的那台；选中后建立连接取回空档期的事件并合并；
- 日志会写明选定与结果：「已选定响应最快的「设备二」…构建连接补齐本机活动数据」、
  「已从「设备二」补齐 10-09 22:00:00 至 10-10 08:00:00 的局域网活动信息（共 128 条）」；
  6 秒内没有任何应答则记「局域网内暂无可用于补齐活动数据的设备（本机最后数据时间 …）」。

**举个完整例子**：

- 设备一 **22:00 关机**，设备二**整晚在线**；第二天设备一开机，广播后发现设备二「从 22:00 之前就一直运行」且响应最快，
  于是从设备二那里**补齐 22:00 到开机这段时间的全部活动信息**；
- 补齐后设备一自己也有了完整历史：**下次别人上线时，设备一同样能作为提供方**把数据给出去——
  这就是「整晚在线的设备负责提供数据」的对称设计；
- 合并时按事件唯一编号去重、按时间升序排列，最多保留 **5000** 条（超出丢弃最旧的），
  所以反复补齐不会出现重复内容；
- 「日志」页能看到广播、应答、选定、补齐的**完整过程**，页面顶部还有一行状态条：
  `局域网活动：最后一次数据获取时间 10-10 08:00:00 · 活动记录 128 条`。

> 补充：未加入内网的空设备也会广播问询（这样它才能发现局域网里有没有活动），但**应答方必须是内网成员**，
> 不会把活动数据泄露给陌生人。

### 1.11 设备数据传输代理（新）

群里发文件 / 发信息时，如果**群里其他成员一个都不在线**，程序不会让内容白白留在本机等着，
而是自动把它**临时寄存在局域网内其他在线成员**的电脑上——这就是「设备数据传输代理」。

- **发起**：文件或信息广播完之后，程序检查群里是否还有人在线；**无人在线**就向局域网内**所有在线成员**
  发出临时寄存请求，日志写：「「设备一」发起在线请求：群「qqq」当前没有其他成员在线，向局域网内所有在线成员请求文件代理」；
- **应答**：收到请求的内网成员立刻回复在线，日志逐条显示「「设备二」（物理地址 11-22-33-44-55-66）回复在线」，
  随后逐台寄存，日志显示「已向「设备二」发送文件代理「作业.txt」（临时寄存，用户不可查看）」（信息类为「已向「设备二」发送信息代理」）；
  没有任何人应答时记「局域网内没有其他在线成员可以代存，代理未建立（文件仍保留在本机）」；
- **寄存形态**：代理文件一律以 **`.proxy` 结尾**（`data/proxy/<proxy_id>.proxy`，原始文件名只记录在元数据里），
  在界面上**不可见、不可打开、不出现在任何列表**，只通过日志体现；只有内网成员参与代理；
- **送达与回收**：相关成员一上线（上线提醒会写日志「上线提醒：「设备二」…已上线」），保存代理的设备自动把内容送达并
  **删除本地代理**；如果群里的成员**一直不上线**（超过设定时间且期间没有任何目标成员上线过），
  就向局域网内其他成员**再扩散一份**（本地保留），日志写「群「qqq」成员一直未上线，已将文件代理「作业.txt」发送给本局域网成员「设备四」一份」；
- **接受后全网清理**：文件 / 信息被目标成员接受后，程序会广播「该代理已被接受」，
  **所有曾经保存过它的设备自动删除**本地代理（接受者作为新的分发源保留）；
  即使某台设备当时不在线、之后才**从别人那里补齐活动历史**，也会在合并历史时执行同样的删除，不会残留垃圾文件。

### 1.12 版本与更新机制

**更新拆成两个独立的更新程序**：主程序 `neiwang.py` / `neiwang.exe` 只负责「检查并提醒」，
真正的更新交给同目录下的 **更新程序1 `neiwang_update1.py`**（C++ 版为 `neiwang_update1.exe`）
与 **更新程序2 `neiwang_update2.py`**（C++ 版为 `neiwang_update2.exe`）。
原来的单一更新程序 `neiwang_update.py` 已删除，双击 `更新.bat` 现在指向的是**更新程序1**。
两个更新程序都不用先开主程序，主程序也只需要同目录有它们即可。

**清单文件 `update.wenyi`**（放在程序目录，同时也放一份到 GitHub / 你的网站）：

```
2.0.0
- 全新 C++ 原生版（纯 Win32 + GDI+，零第三方依赖），与 Python 版协议完全兼容、可同网混用
- 新增「局域网活动历史」：启动自动广播物理地址/IP/最后一次数据获取时间，由连续运行最久的设备补齐空档
- 新增「设备数据传输代理」：群内无人在线时把文件或信息临时寄存到局域网在线设备，上线后自动送达并回收
- 新增空设备启动提示「当前没有局域网网络活动，是否新建？」
- 更新程序改为双更新程序：更新程序1 更新除自己外的全部，更新程序2 更新更新程序1
- 保留 v1.1 全部功能：内网准入与入网投票、群聊、私聊、离线保密转存、群文件与离线回退、改名投票、公共日志
```

- **第一行 = 版本号**，其余各行 = 本次更新内容（也可以写成 JSON：`{"version": "2.0.0", "notes": ["..."]}`）。
- 程序**自己的版本号也取自本机 `update.wenyi` 的第一行**——发布新版本时只改这一个文件即可。
- **主程序 `neiwang.py` 每次启动都会自动检查更新**，但只在真的有更新时才打扰你：
  **无网络、或远程版本号与本地相同（或更旧）→ 完全静默、不弹任何窗口**；
  只有发现**更新**（远程版本更高）时才弹窗：

```
新版本 —— v2.0.1

更新内容：
- 修复了 xxx
- 新增了 yyy

（当前版本 v2.0.0）

「是」启动更新程序1 立即更新；
「否」打开更新发布页手动下载；「取消」稍后再说。
```

**两个更新程序的命令行参数（完全一致）：**

| 参数 | 行为 |
| --- | --- |
| （无参数） | 手动模式，一定会给出明确反馈（已经是最新版本 / 无法连接更新服务器 / 发现新版本并弹窗） |
| `--auto` | 自动模式，静默——只有发现新版本才弹窗 |
| `--update` | 不再询问，直接开始更新（主程序点「是」后就是这样调起它的） |
| `--check` | 无界面检查，只打印一行结果（`UPDATE_AVAILABLE 版本号` / `UP_TO_DATE 版本号` / `OFFLINE`） |
| `--patch-updater1` | **只属于更新程序2**：不检查、不下载，直接把 `update_clone/` 里的更新程序1 覆盖到程序目录 |
| `--wait-pid <pid>` | 等待指定进程退出（更新程序1 用它把 pid 交给更新程序2，C++ 版超时 30 秒） |
| `--root <path>` | 指定更新工作目录（C++ 版参数；Python 版用环境变量 `NEIWANG_UPDATE_ROOT`） |

**更新三步（沿用原有流程，由更新程序1 完成）：**

1. 把当前 `data/` 目录（**用户所有会话内容**：群组、聊天、文件索引、转存记录）完整备份到
   程序目录下的新文件夹 **`customer_god/`**；
2. 把新版本取到程序目录的 **`update_clone/`**：装了 Git 且配置了 `update_repo` 时用
   `git clone --depth 1`（浅克隆）；否则**直接下载 ZIP 更新包并解压**——
   不需要安装 Git，适合内网部署；
3. 把 `customer_god/` 里的会话内容**回填**到 `update_clone/data/` 目录。

**更新程序1 的第四步：就地更新「除自己以外的全部文件」**：

4. 把 `update_clone/` 里的文件按相对路径**覆盖到程序目录**，但**跳过** `data/`（本机数据不动）、
   `customer_god/`、`update_clone/`（运行时目录）以及**更新程序1 自己**；
   同时删除「`update_clone/` 里已经没有、但属于程序文件」的旧文件（`*.py`、`*.exe`、`*.bat`、
   `update.wenyi`、`README.md`、`*.md`（`docs/` 除外））。
5. 记录 `.update_manifest_applied`（版本号 + 时间），并往 `update_clone.log` 追加一行日志。

**更新程序2 的第五步：更新更新程序1 自己**：

- 更新程序1 就地更新完成后，会带 **`--patch-updater1 --wait-pid <pid>`** 调起**更新程序2**
  （优先用 `update_clone/` 里的新版，其次用程序目录里的）；
- 更新程序2 **只做一件事**：把 `update_clone/` 里的更新程序1 覆盖到程序目录。
  Windows 上正在运行的 exe 不能覆盖自身，所以更新程序2 会先等更新程序1 退出（超时 30 秒）；
  仍然失败就把新文件写成 `neiwang_update1.new.exe` 并提示重启；
- 完成后日志写「更新程序1 已由更新程序2 更新到 v<版本号>」。

完成后提示新版本路径，并可一键打开新版本目录 / 启动新版本（`启动.bat`），聊天和文件都不会丢。
失败时会明确说明原因（没装 Git 且没配置 `update_package`、仓库地址没配置、网络不通等）。

**相关配置（`data/config.json`）**：

| 字段 | 说明 |
| --- | --- |
| `update_url` | 更新清单地址（已默认指向本仓库 raw）：`https://raw.githubusercontent.com/ZZZ-need-sleep/Local_Network_Communication-created-by-DeepDeek-/main/update.wenyi` |

| `update_package` | ZIP 更新包下载地址（例：`http://内网服务器/内部网.zip`）；在没装 Git 的内网环境用它更新 |

### 1.14 常见问题

- **两台电脑互相看不见？** 确认在同一局域网同一网段；允许 Python 通过防火墙；确认路由器没开 AP 隔离。
- **为什么点「创建群组」提示先加入内网？** 内网是准入层：没入网时程序是空的。启动后程序会自动扫描附近内网——
  有就申请加入（人多时需要成员投票），没有就自己建一个；也可以到「内网」页手动申请或自行建立。
- **左侧「投票」图标上的小红点是什么？** 有同学申请加入内网、需要你投票。鼠标移上去才会弹出面板
  （不会自动打扰），投完小红点消失；投错了 5 分钟内可以在「投票」页或「更多」页改票。
- **我的物理地址为什么显示成 `RND-XXXX-XXXX-XXXX`？** 说明这台机器取不到网卡 MAC（常见于虚拟机），
  程序生成了一个持久随机 ID 当物理地址，一样会被登记、一样参与投票。
- **端口被占用？** 程序会自动尝试 45431 之后的端口；UDP 45455 只用于广播发现。
- **发送人关机后文件还能下吗？** 能——只要有其他同学下载过该文件并在线，就会自动从他那里取。
- **退出群组会删文件吗？** 不会，已下载文件保留在本机。
- **改名改不了了？** 说明你已经改过一次，需要超过 5 位同学投票同意；人数不够时可以在 `config.json` 调低 `rename_vote_need`。
- **私聊对方离线会丢消息吗？** 不会，会自动加密转存到在线同学处，对方上线后自动送达。
- **C++ 版和 Python 版能一起用吗？** 能。两版协议完全兼容，可以在同一个内网、同一个群里互发消息和文件；数据目录结构也一样。
- **关机期间别人发的消息我还能看到吗？** 能。本机的「局域网活动历史」会在启动时向局域网广播，由「连续运行最久、响应最快」的设备补齐你错过的那段时间。
- **为什么日志里出现 `.proxy` 文件？** 那是「设备数据传输代理」的临时寄存内容（群内无人在线时才会用到），界面上不可见、不可打开，送达后会自动删除。
- **更新失败怎么办？** 按取包方式排查：① 用 Git 方式的话，确认装了 Git（`git --version`）并配置了 `update_repo`；② 没装 Git 就在 `data/config.json` 里配置 `update_package`（ZIP 更新包的下载地址）；③ 以上都正常，再检查网络能否访问更新服务器 / 仓库；④ 如果提示 `neiwang_update1.new.exe`，说明更新程序1 当时还在运行，重启一次即可完成替换。
- **怎么干净退出？** 点窗口关闭按钮即可，所有状态自动保存。

### 2.1 專案簡介

内部网 區域網路群組（簡稱「班群助手」）提供 **Python 版** 與 **C++ 原生版** 兩套同等級的實作：

- **兩版都零第三方相依**：Python 版只使用 `socket / threading / tkinter / hashlib / hmac / json / urllib / subprocess` 等標準函式庫，整個資料夾複製過去就能執行；C++ 版只用 Windows 內建的 Win32 + GDI+；
- **C++ 原生版不需要安裝 Python**：編譯出單一檔案 `neiwang.exe`，複製過去雙擊即可執行，適合不想逐台安裝執行環境的班級（詳見 2.4 節）；
- **不需要伺服器**：沒有中央伺服器，所有電腦平等互連，先建立群組的人就是群主電腦，其他人用群號加入；
- **介面仿微信 4.x 桌面版**：左側窄圖示列（聊天 / 日誌）+ 中間群組清單（搜尋、未讀紅點、右鍵選單）+ 右側聊天泡泡主區（微信綠、圓形頭像、群檔案、成員清單）；
- **針對班級情境**：作業互傳、通知廣播、臨時聊天，區域網路內不需要外網也能使用。

### 2.4 C++ 原生版（新）

除了 Python 版，本專案還提供一套**完全獨立的 C++ 原生版**：純 Win32 + GDI+ 自繪介面、零第三方相依，
編譯後就是單一檔案 `neiwang.exe`。兩版**同等級、功能對齊**，可以只用其中一種，也可以混用。

- **為什麼有 C++ 版**：不必在每台電腦安裝 Python 與 tkinter；單一 exe 複製即用、啟動快、不留黑色主控台視窗；適合不方便逐台安裝環境的電腦教室；
- **協定完全相容**：網路封包、連接埠（UDP 45455 / TCP 45431）與資料檔格式和 Python 版完全一致，
  兩版可以在同一個內網、同一個群組裡互相收發訊息與檔案（部分電腦用 Python 版、部分用 C++ 版也沒問題）；
- **如何建置**：安裝 Visual Studio 2022 建置工具（勾選「使用 C++ 的桌面開發」工作負載與 Windows SDK）後，
  雙擊 **`构建C++版.bat`**（內部呼叫 `cpp\build.bat all`），或於命令列執行 `cpp\build.bat all`；
  產物在 **`cpp\build\`**：`neiwang.exe`、`neiwang_update1.exe`、`neiwang_update2.exe` 與測試用的 `test_*.exe`；
- **如何執行**：雙擊 **`启动C++版.bat`**（尚未建置會自動先建置），或直接執行 `cpp\build\neiwang.exe`；資料目錄同樣是程式目錄下的 `data/`；
- **如何更新**：雙擊 **`更新C++版.bat`**（等同執行 `neiwang_update1.exe`，再由它驅動 `neiwang_update2.exe`，見 2.12 節）；
- **與 Python 版的差異**：介面為 Win32 自繪（外觀與 Python 版一致：圓角、微信綠、同樣的三欄版面）；資料目錄 `data/` 結構完全相同，可直接互換使用。

### 2.5 內網准入與入網投票（新）

程式會把同一個區域網路裡的電腦組成一個「**內網**」：**沒被接納的電腦，程式就是空的**
（群組、聊天、檔案都不能用）。每台電腦的**物理位址（MAC）**會登記在成員表裡，全網同步、人人可見。

**啟動時自動做的事**：已在内網 → 廣播自己；還沒有 → 先**掃描**附近的內網：
掃到就自動**申請加入**，沒掃到就**自行建立**（自己成為發起者）。

**入網投票門檻**：

| 內網現有成員 | 新成員加入需要 |
| --- | --- |
| **≤ 5 人** | 免投票，自動通過 |
| **6 – 7 人** | **全票通過** |
| **≥ 8 人** | 同意票**超過 1/3**（8 人需 3 票、9 人需 4 票） |

**投票方式**：所有入網申請統一收在左側「**投票**」圖示裡（有待投票時出現**小紅點**；
**滑鼠靠近才彈出面板**）。每項可選 **同意 / 拒絕 / 棄權**；投完小紅點消失；
**5 分鐘內可改票**；**一次投票有效期 1 天**，逾期視為結束；歷史投票在左側「**更多**」頁；
**沒有「自動同意」**，必須由人來點。

> 取不到網卡 MAC 的機器會自動產生持久隨機 ID 當物理位址（`RND-XXXX-XXXX-XXXX`），一樣會登記。

### 2.6 快速開始

> **首次啟動會自動組網**：掃描附近內網——找到就申請加入（人多時需成員投票），
> 找不到就自己建立；**加入內網之後**才會出現群組功能（詳見 2.5 節）。

1. 每台電腦安裝 **Python 3.8+**（Windows 安裝時記得勾選 *Add Python to PATH*）。
2. 把整個資料夾複製到每台電腦（USB 隨身碟 / 雲端硬碟 / 共用資料夾都可以，不需要放在相同路徑）。
3. Windows 雙擊 **`啟動.bat`**；其他系統於命令列執行 `python neiwang.py`。
4. **建立群組**：點「＋ 建立群組」輸入群組名稱（例如：高三（2）班），程式自動產生 **6 位群號**。
5. **加入群組**：其他同學點「加入群組」→ 自動掃描區域網路中發現的群組 → 選取加入；也可手動輸入群號。
6. **改名**：點左下角頭像（或「設定」）→ 輸入新名字。**第一次改名直接生效**；之後的修改會發起投票。
7. **聊天**：選取群組 → 打字按 Enter 傳送。
8. **私聊**：群組內切到「成員」頁 → 點某位同學的頭像（或直接點聊天中對方的頭像）→ 彈出私聊視窗。
9. **傳檔案**：點「📎 傳送檔案」→ 選檔案 → 全群組成員自動下載 → 完成後彈系統通知。
10. **看檔案**：切到「群組檔案」頁，雙擊檔案即可用系統預設程式開啟。

> 建議：把群號告訴大家，由一台電腦建立群組即可，所有加入者共用同一個群組。

### 2.7 改名投票規則

- **第一次改名**：在「設定」中直接儲存，立即生效，不需要任何人同意。
- **第二次及之後**：點「儲存名字」會向區域網路廣播投票請求，其他線上使用者會彈出
  「某某申請把名字從 A 改為 B，是否同意？」→ 點「同意 / 拒絕」。
- **生效條件**：收到**超過 5 名使用者**的同意票（預設值，可在 `data/config.json` 的
  `rename_vote_need` 修改）；**120 秒**內票數不足則失敗，可以重新發起。
- **防灌票**：同一台電腦對同一次投票只計一票；每次投票都有唯一編號，互不干擾。
- 申請與通過結果都會寫入公共日誌，全員可見。

### 2.8 雙人私聊與離線保密轉存

**私聊入口**：群組「成員」頁點成員頭像，或聊天區點對方頭像 / 名字。

**對方在線時**：訊息定向傳送，只有收件者收到，其他人不顯示、不記日誌。

**對方離線時（保密轉存）**，過程完全自動：

1. 你的程式把訊息用**隨機金鑰加密**（每則訊息一把新金鑰），轉存給某位在線的同學 C；
2. **C 全程無感**：沒有彈窗、沒有日誌、介面上看不到，磁碟裡只有密文；
3. 對方 B 一上線（心跳廣播），C 的程式自動把密文包直連送達給 B；
4. B 解密並做 **HMAC 完整性校驗**，完整才回執；C 收到回執後**刪除**轉存內容；
   校驗失敗則保留重試（最多 3 次）；
5. B 的介面像一般私聊一樣顯示，並帶「離線轉存送達」標記。

> 說明：轉存使用純標準函式庫串流加密 + HMAC 做「機器級」保密與完整性校驗（轉存方使用者無法在應用程式裡查看）。
> 如需抵抗「轉存方直接翻磁碟」的更強保密，可升級為非對稱加密。

### 2.9 群組檔案分發策略

1. **傳送者在線** → 接收者直接向傳送者電腦**點對點下載**（SHA-256 校驗，損壞自動重試）。
2. **傳送者離線** → 在「日誌」中**公共詢問**（全網可見、人人可看不可操作）：
   其他下載過該檔案的電腦自動回報自己的區域網路 IP（沒下載過則無回應），
   請求方自動向**第一個回應的 IP** 請求檔案，全程無需兩端使用者操作。
3. 加入群組時會自動同步該群組檔案清單，錯過的檔案會自動補下載。

### 2.10 區域網路活動歷史（新）

程式會把區域網路裡發生過的活動（公共日誌、群組聊天、代理操作、系統 / 上線提醒）持久化成本機的
**區域網路活動歷史**（`data/active_log.json`），並讓裝置之間互相補齊——**關機、斷網期間錯過的資訊不會遺失**。

- **空裝置啟動提示**：若「只有程式、沒有任何區域網路相關資料」（未入內網、沒有活動歷史、沒有任何群組），
  啟動後會彈出對話框：標題 `内部网`、正文 **「当前没有局域网网络活动，是否新建？」**，
  按鈕為 **`是，新建（推荐）`** 與 **`否，稍后`**；選「是」→ 建立內網並開啟「新增群組」；
  選「否」→ 只在日誌寫「当前没有局域网网络活动（未新建）」。**本機已有活動資料時不會彈出**，改走下面的自動補齊流程；
- **有資料時啟動會自動補齊**：啟動時（之後每 60 秒）廣播自己的**實體位址 + 本機 IP + 最後一次資料取得時間**、活動筆數與連續執行起始時間；
  內網其他裝置收到後**立刻回應校驗資料**，日誌逐條記下「收到「裝置二」（實體位址 11-22-33-44-55-66）的區域網路活動校驗資料：連續執行自 …，最後資料 …，共 N 條」；
- **如何挑選提供方**：請求方在 **6 秒**視窗內挑出「從我的最後資料時間之前就一直執行」的合格回應，並在其中選**最先到達（回應最快）**的一台，
  建立連線取回空檔期事件；若 6 秒內沒有任何回應，日誌記「區域網路內暫無可用於補齊活動資料的裝置」；
- **舉例**：裝置一 **22:00 關機**、裝置二**整晚在線**；隔天裝置一開機，發現裝置二「從 22:00 之前就一直執行」且回應最快，
  於是**補齊 22:00 到開機之間的全部活動資訊**；補齊後裝置一自己也成為提供方，**下次別人上線時它同樣能把資料給出去**；
- **合併規則**：以事件唯一編號去重、依時間升序排列，最多保留 **5000** 筆（超出丟棄最舊的），反覆補齊不會出現重複內容；日誌頁面頂端另有狀態列 `區域網路活動：最後一次資料取得時間 10-10 08:00:00 · 活動記錄 128 筆`。

### 2.11 裝置資料傳輸代理（新）

在群組裡傳檔案 / 傳資訊時，如果**群組裡其他成員一個都不在線**，程式會把內容**暫時寄存到區域網路上其他線上成員**的電腦——
這就是「裝置資料傳輸代理」。

- **發起與回應**：群組內無人在線時，程式向區域網路內**所有線上成員**發出暫時寄存請求，日誌寫「「裝置一」發起線上請求：群「qqq」目前沒有其他成員在線，向區域網路內所有線上成員請求檔案代理」；
  收到請求的內網成員立刻回覆在線，日誌逐條顯示「「裝置二」（實體位址 11-22-33-44-55-66）回覆在線」與「已向「裝置二」傳送檔案代理「作業.txt」（暫時寄存，使用者不可查看）」；
  **所有人都沒回應**時記「區域網路內沒有其他線上成員可以代存，代理未建立（檔案仍保留在本機）」；
- **寄存形態**：代理檔案一律以 **`.proxy`** 結尾（`data/proxy/<代理編號>.proxy`，原始檔名只記在中介資料裡），
  介面上**看不見、打不開、不會出現在任何清單**，只透過日誌呈現；只有內網成員參與代理；
- **送達與回收**：相關成員一上線（會先寫上線提醒日誌），保存代理的裝置自動送達並**刪除本機代理**；
  若群組成員**一直不上線**（超過設定時間且期間沒有任何目標成員上線），就向區域網路內其他成員**再擴散一份**（本機保留）；
- **被接受後全網清理**：內容被目標成員接受後會廣播「代理已被接受」，**所有曾保存過它的裝置自動刪除**本機代理；
  即使某台裝置當時不在線、之後才**從別人那裡補齊活動歷史**，合併歷史時也會執行同樣的刪除。

### 2.12 版本與更新機制

**更新拆成兩個獨立的更新程式**：主程式 `neiwang.py` / `neiwang.exe` 只負責「檢查並提醒」，
真正的更新交給同目錄下的 **更新程式1 `neiwang_update1.py`**（C++ 版為 `neiwang_update1.exe`）
與 **更新程式2 `neiwang_update2.py`**（C++ 版為 `neiwang_update2.exe`）。
原本的單一更新程式 `neiwang_update.py` 已刪除，雙擊 `更新.bat` 現在指向的是**更新程式1**。

**清單檔案 `update.wenyi`**（放在程式目錄，同時也放一份到 GitHub / 你的網站）：

```
2.0.0
- 全新 C++ 原生版（純 Win32 + GDI+，零第三方相依），與 Python 版協定完全相容、可同網混用
- 新增「區域網路活動歷史」：啟動自動廣播實體位址/IP/最後一次資料取得時間，由連續執行最久的裝置補齊空檔
- 新增「裝置資料傳輸代理」：群組內無人在線時把檔案或資訊暫時寄存到區域網路線上裝置，上線後自動送達並回收
- 新增空裝置啟動提示「当前没有局域网网络活动，是否新建？」
- 更新程式改為雙更新程式：更新程式1 更新除自己外的全部，更新程式2 更新更新程式1
- 保留 v1.1 全部功能：內網准入與入網投票、群組聊天、私聊、離線保密轉存、群組檔案與離線回退、改名投票、公共日誌
```

- **第一行 = 版本號**，其餘各行 = 本次更新內容（也可寫成 JSON：`{"version": "2.0.0", "notes": ["..."]}`）。
- 程式**自己的版本號也取自本機 `update.wenyi` 的第一行**——發布新版本時只要改這一個檔案。
- **主程式 `neiwang.py` 每次啟動都會自動檢查更新**，但只在真的有更新時才打擾你：
  **無網路、或遠端版本號與本機相同（或更舊）→ 完全靜默、不彈任何視窗**；
  只有發現**更新**（遠端版本較高）時才彈窗：

```
新版本 —— v2.0.1

更新內容：
- 修復了 xxx
- 新增了 yyy

（目前版本 v2.0.0）

「是」啟動更新程式1 立即更新；
「否」開啟更新發布頁手動下載；「取消」稍後再說。
```

**兩個更新程式的命令列參數（完全一致）：**

| 參數 | 行為 |
| --- | --- |
| （無參數） | 手動模式，一定會給出明確回饋（已經是最新版本 / 無法連線更新伺服器 / 發現新版本並彈窗） |
| `--auto` | 自動模式，靜默——只有發現新版本才彈窗 |
| `--update` | 不再詢問，直接開始更新（主程式點「是」後就是這樣叫起它） |
| `--check` | 無介面檢查，只印出一行結果（`UPDATE_AVAILABLE 版本號` / `UP_TO_DATE 版本號` / `OFFLINE`） |
| `--patch-updater1` | **只屬於更新程式2**：不檢查、不下載，直接把 `update_clone/` 裡的更新程式1 覆蓋到程式目錄 |
| `--wait-pid <pid>` | 等待指定行程結束（更新程式1 用它把 pid 交給更新程式2，C++ 版逾時 30 秒） |
| `--root <path>` | 指定更新工作目錄（C++ 版參數；Python 版使用環境變數 `NEIWANG_UPDATE_ROOT`） |

**更新三步（沿用原有流程，由更新程式1 完成）：**

1. 把目前 `data/` 目錄（**使用者所有會話內容**：群組、聊天、檔案索引、轉存紀錄）完整備份到
   程式目錄下的新資料夾 **`customer_god/`**；
2. 把新版本取到程式目錄的 **`update_clone/`**：裝了 Git 且設定了 `update_repo` 時用
   `git clone --depth 1`（淺層複製）；否則**直接下載 ZIP 更新包並解壓縮**——
   不需要安裝 Git，適合內網部署；
3. 把 `customer_god/` 裡的會話內容**回填**到 `update_clone/data/` 目錄。

**更新程式1 的第四步：就地把「除自己以外的全部檔案」更新掉**：

4. 把 `update_clone/` 裡的檔案依相對路徑**覆蓋到程式目錄**，但**跳過** `data/`（本機資料不動）、
   `customer_god/`、`update_clone/` 與**更新程式1 自己**；同時刪除「`update_clone/` 已經沒有、但屬於程式檔案」的舊檔
   （`*.py`、`*.exe`、`*.bat`、`update.wenyi`、`README.md`、`*.md`（`docs/` 除外））；
5. 記錄 `.update_manifest_applied`（版本號 + 時間），並往 `update_clone.log` 追加一行日誌。

**更新程式2 的第五步：更新更新程式1 自己**：

- 更新程式1 就地更新完成後，會帶 **`--patch-updater1 --wait-pid <pid>`** 叫起**更新程式2**
  （優先使用 `update_clone/` 裡的新版，其次用程式目錄裡的）；
- 更新程式2 **只做一件事**：把 `update_clone/` 裡的更新程式1 覆蓋到程式目錄。Windows 上正在執行的 exe 不能覆蓋自身，
  所以更新程式2 會先等更新程式1 結束（逾時 30 秒）；仍然失敗就把新檔案寫成 `neiwang_update1.new.exe` 並提示重開；
- 完成後日誌寫「更新程式1 已由更新程式2 更新到 v<版本號>」。

完成後提示新版本路徑，並可一鍵開啟新版本目錄 / 啟動新版本（`啟動.bat`），聊天和檔案都不會遺失。
失敗時會明確說明原因（沒安裝 Git 且沒設定 `update_package`、倉庫位址沒設定、網路不通等）。

**相關設定（`data/config.json`）**：

| 欄位 | 說明 |
| --- | --- |
| `update_url` | 更新清單位址（已預設指向本儲存庫 raw）：`https://raw.githubusercontent.com/ZZZ-need-sleep/Local_Network_Communication-created-by-DeepDeek-/main/update.wenyi` |
| `update_page` | 「否」按鈕開啟的更新發布頁（已預設指向本儲存庫首頁：`https://github.com/ZZZ-need-sleep/Local_Network_Communication-created-by-DeepDeek-`） |
| `update_repo` | Git 方式更新用的儲存庫位址：`https://github.com/ZZZ-need-sleep/Local_Network_Communication-created-by-DeepDeek-.git` |
| `update_package` | ZIP 更新包下載位址（例：`http://內網伺服器/內部網.zip`）；在沒安裝 Git 的內網環境用它更新 |

> 提示：`update_url` / `update_repo` 這兩個位址已預設指向上面的儲存庫。若你的預設分支是 `master` 而不是 `main`，
> 請把程式碼（或 `config.json`）裡的 `main` 改成 `master`。

### 2.14 常見問題

- **兩台電腦互相看不見？** 確認在同一區域網路同一網段；允許 Python 通過防火牆；確認路由器沒開 AP 隔離。
- **連接埠被占用？** 程式會自動嘗試 45431 之後的連接埠；UDP 45455 只用於廣播探索。
- **傳送者關機後檔案還能下載嗎？** 可以——只要有其他同學下載過該檔案且在線，就會自動從他那裡取得。
- **退出群組會刪檔案嗎？** 不會，已下載檔案保留在本機。
- **改名改不了？** 表示你已經改過一次，需要超過 5 位同學投票同意；人數不足時可在 `config.json` 調低 `rename_vote_need`。
- **私聊對方離線會丟訊息嗎？** 不會，會自動加密轉存到在線同學處，對方上線後自動送達。
- **C++ 版和 Python 版能一起用嗎？** 能。兩版協定完全相容，可以在同一個內網、同一個群組裡互傳訊息與檔案；資料目錄結構也一樣。
- **關機期間別人發的訊息我還能看到嗎？** 能。本機的「區域網路活動歷史」會在啟動時廣播，由「連續執行最久、回應最快」的裝置補齊你錯過的那段時間。
- **為什麼日誌裡出現 `.proxy` 檔案？** 那是「裝置資料傳輸代理」的暫時寄存內容（群組內無人在線時才會用到），介面上看不見、打不開，送達後會自動刪除。
- **更新失敗怎麼辦？** 依取包方式排查：① 用 Git 方式的話，確認安裝了 Git（`git --version`）並設定了 `update_repo`；② 沒安裝 Git 就在 `data/config.json` 裡設定 `update_package`（ZIP 更新包的下載位址）；③ 以上都正常，再檢查網路能否連上更新伺服器 / 儲存庫；④ 若提示 `neiwang_update1.new.exe`，表示更新程式1 當時仍在執行，重開一次即可完成取代。
- **怎麼乾淨結束？** 點視窗關閉按鈕即可，所有狀態自動儲存。

## 三、Русский

### 3.1 О проекте

内部网 LAN Group («помощник для класса») — программа для группового общения и обмена файлами
в локальной сети. Доступны **две равнозначные реализации**: на **чистой стандартной библиотеке Python**
и **нативная версия на C++** (чистый Win32 + GDI+, один исполняемый файл, Python не требуется).

- **Без сторонних зависимостей в обеих версиях**: в Python-версии используются лишь `socket / threading / tkinter / hashlib / hmac / json / urllib / subprocess` — достаточно скопировать папку и запустить; C++-версия использует только встроенные Win32 + GDI+;
- **Версии на C++ не нужен Python**: компилируется один файл `neiwang.exe`, который достаточно скопировать и запустить (см. раздел 3.4);
- **Без сервера**: центрального сервера нет, все компьютеры равноправны; тот, кто создал группу, становится её «хостом», остальные подключаются по номеру группы.
- **Интерфейс в стиле WeChat 4.x для Windows 11**: узкая панель иконок слева (чат / журнал), список групп в центре (поиск, красные индикаторы непрочитанного, контекстное меню), справа — область чата с «пузырями» (зелёный акцент, круглые аватары, файлы группы, список участников).
- **Для школы**: обмен домашними заданиями, объявления, переписка — всё внутри локальной сети, интернет не требуется.

### 3.2 Требования к окружению (важно)

| Пункт | Требование |
| --- | --- |
| Python | **3.8 или новее** (рекомендуется 3.10+). Официальный установщик Python **уже включает tkinter**. **Нужен только для Python-версии**, C++-версии Python не требуется |
| Версия на C++ | **Windows 10 / 11**; для запуска **Python не нужен** — один файл `neiwang.exe`. Для сборки нужны **средства сборки Visual Studio 2022 (Build Tools)** с рабочей нагрузкой «Разработка классических приложений на C++» и Windows SDK |
| Операционная система | **Windows 10 / 11 (рекомендуется)**; также Windows 7 / 8.1, Linux, macOS |
| Сторонние библиотеки | **нет**, `pip install` не нужен вообще |
| Сеть | все компьютеры в **одной локальной сети / одном сегменте** (один роутер, коммутатор или школьная сеть), широковещательные **UDP**-пакеты разрешены |
| Порты | UDP **45455** (обнаружение), TCP **45431** (передача файлов, пересылка личных сообщений; при занятости порт автоматически сдвигается, до 20 попыток) |
| Брандмауэр | при первом запуске Windows появится запрос — нажмите **«Разрешить»** (хотя бы для частных сетей), иначе вас не увидят |
| Права | достаточно обычного пользователя, **администратор не нужен** |
| Диск | сама программа < 200 КБ; история и кэш файлов — в папке `data/` |
| Git (необязательно) | нужен **только** при обновлении через Git; без Git можно обновляться ZIP-пакетом (`update_package`). Обновление выполняют **две отдельные программы обновления** (обновлятор 1 и обновлятор 2) из той же папки |

**Особенности платформ:**

- **Windows (рекомендуется)**: системные всплывающие уведомления (`Shell_NotifyIcon`), скруглённые окна Windows 11;
  запуск — двойной щелчок по `启动.bat` (скрипт использует `pythonw`, консоль не появляется).
- **Linux**: нужен tkinter (`sudo apt install python3-tk` в Debian/Ubuntu, `sudo dnf install python3-tkinter` в Fedora);
  уведомления показываются окном внутри программы; файлы открываются через `xdg-open`.
- **macOS**: используйте Python с python.org (в нём есть tkinter); уведомления — окном; файлы открываются через `open`.
- **Сеть**: если в школьном Wi-Fi включена изоляция клиентов (AP isolation), широковещательные пакеты
  отбрасываются, и компьютеры не видят друг друга — используйте один роутер/коммутатор или обычный Wi-Fi.

### 3.3 Возможности

| Возможность | Описание |

| Файлы группы | Отправка файлов в группу, участники **скачивают автоматически**; двойной щелчок открывает файл системной программой |
| Резервный источник файлов | Если отправитель выключил компьютер, программа публично спрашивает в журнале — тот, у кого файл уже есть, отдаёт его |
| Голосование за смену имени | Имя выбирается свободно; **первая смена — бесплатно**, дальше нужно больше 5 голосов «за» |
| Общий журнал | Вкладка «Журнал»: общий журнал локальной сети, виден всем, **только для чтения** |
| Версия на C++ | **Равноценная** вторая реализация (чистый Win32 + GDI+, один exe, Python не нужен); протокол полностью совместим, обе версии работают в одной сети |
| История активности в локальной сети | При запуске рассылает **физический адрес + IP + время последнего получения данных** и сверяет данные с другими; пропущенное за время выключения/отключения дополняется от устройства, работающего дольше всех |
| Прокси передачи данных | Если в группе никого нет в сети, файл или сообщение временно размещается на других онлайн-устройствах локальной сети (суффикс меняется на `.proxy`, пользователю не видно), а при появлении адресата доставляется и удаляется автоматически |
| Приём в сеть | Реестр **физических адресов (MAC)**: без принятия в сеть программа пуста. При запуске — поиск соседних сетей: нашли → заявка, не нашли → создаём свою |
| Голосование за вступление | **≤5 участников** — без голосования, **6–7** — единогласно, **≥8** — более 1/3; можно воздержаться и изменить голос |
| Проверка обновлений | Проверяется автоматически при запуске; без сети или при той же версии — молча; окно появляется только при новой версии («Новая версия — v…» и список изменений), а обновление выполняют **две программы обновления** из той же папки (обновлятор 1 обновляет все файлы, кроме себя, обновлятор 2 обновляет сам обновлятор 1) |
| Системные уведомления | По завершении загрузки файла: `«qqq»群「AA」的「你好」下载完毕` |

### 3.4 Версия на C++ (новое)

Помимо Python-версии в проекте есть **полностью самостоятельная нативная версия на C++**: интерфейс нарисован
на чистом Win32 + GDI+, сторонних зависимостей нет, на выходе — один файл `neiwang.exe`.
Обе версии **равноценны**, можно использовать одну из них или обе сразу.

- **Зачем нужна версия на C++**: не нужно ставить Python и tkinter на каждый компьютер; один exe — скопировал и запустил, быстрый старт, без лишнего чёрного окна консоли.
- **Полная совместимость протокола**: сетевые пакеты, порты (UDP 45455 / TCP 45431) и форматы файлов данных совпадают с Python-версией, поэтому обе версии **работают в одной внутренней сети и в одной группе** — часть компьютеров может быть на Python, часть на C++.
- **Сборка**: установите средства сборки Visual Studio 2022 (рабочая нагрузка «Разработка классических приложений на C++» и Windows SDK), затем запустите `构建C++版.bat` (внутри вызывается `cpp\build.bat all`) либо выполните `cpp\build.bat all` в командной строке; результат — в `cpp\build\`: `neiwang.exe`, `neiwang_update1.exe`, `neiwang_update2.exe` и тестовые `test_*.exe`.
- **Запуск**: `启动C++版.bat` (если сборки нет — соберёт автоматически) или напрямую `cpp\build\neiwang.exe`; папка данных — та же `data/`.
- **Обновление**: `更新C++版.bat` (запускает `neiwang_update1.exe`, который затем вызывает `neiwang_update2.exe`, см. раздел 3.12).
- **Отличия от Python-версии**: интерфейс нарисован средствами Win32 (внешний вид одинаковый: скругления, зелёный акцент, три области); структура `data/` полностью идентична, данные можно переносить между версиями.

### 3.5 Приём во «внутреннюю сеть» и голосование (новое)

Программа объединяет компьютеры локальной сети во «**внутреннюю сеть**»: **пока вас не приняли,
программа пуста** — группы, чат и файлы недоступны. **Физический адрес (MAC)** каждой машины
заносится в общий реестр участников, который синхронизируется по всей сети.

**Что происходит при запуске**: если вы уже в сети — рассылаете объявление; если нет — сначала
**поиск** соседних сетей: нашли → автоматически **заявка на вступление**; не нашли → **создаёте свою**
(становитесь основателем).

**Порог голосования**:

| Участников в сети | Что нужно новичку |
| --- | --- |
| **≤ 5** | без голосования, автоматически |
| **6–7** | **единогласно** |
| **≥ 8** | **более 1/3** голосов «за» (8 → 3, 9 → 4, 12 → 5) |

**Как голосовать**: все заявки собраны под иконкой «**Голосование**» слева — появляется **красная
точка**, панель открывается **только при наведении мыши**. Варианты: **за / против / воздержаться**.
После голосования точка исчезает; **изменить голос можно в течение 5 минут**; **голосование действует
1 день**, после чего считается завершённым; история — в разделе «**Ещё**».
**Автоматического согласия нет** — всегда решает человек.

> Если MAC-адрес недоступен (например, в виртуальной машине), программа создаёт постоянный
> случайный идентификатор (`RND-XXXX-XXXX-XXXX`) и использует его как физический адрес.

### 3.6 Быстрый старт

1. Установите **Python 3.8+** на каждый компьютер (в Windows отметьте *Add Python to PATH*); **если не хотите ставить Python — используйте версию на C++** (раздел 3.4).
2. Скопируйте всю папку на каждый компьютер (USB-флешка, облако, общая папка — путь может быть любым).
3. В Windows запустите **`启动.bat`**; в других системах — `python neiwang.py` в терминале. Для версии на C++: **`启动C++版.bat`** (или `cpp\build\neiwang.exe`).
4. **Создать группу**: «＋ 创建群组» → введите название (например, «10-А класс») → программа создаст **6-значный номер группы**.
5. **Войти в группу**: «加入群组» → автоматический поиск групп в сети → выберите и войдите; либо введите номер вручную.
6. **Сменить имя**: аватар в левом нижнем углу (или «设置») → введите новое имя. **Первая смена применяется сразу**, дальше — голосование.
7. **Чат**: выберите группу → введите текст и нажмите Enter.
8. **Личные сообщения**: вкладка «成员» → нажмите на аватар участника (или на аватар в чате).
9. **Файлы**: «📎 发送文件» → выберите файлы → участники скачают автоматически → придёт системное уведомление.
10. **Просмотр файлов**: вкладка «群文件» → двойной щелчок открывает файл.

> Совет: сообщите всем номер группы; группу достаточно создать на одном компьютере — все войдут в неё же.

### 3.7 Правила голосования за смену имени

- **Первая смена имени** — сохраняется сразу, без чьего-либо согласия.
- **Вторая и последующие** — при нажатии «保存名字» в сеть отправляется запрос на голосование;
  у остальных участников появляется окно «Такой-то хочет сменить имя с A на B — согласны?» с кнопками «同意 / 拒绝».
- **Условие принятия**: **больше 5 голосов «за»** (значение по умолчанию, меняется в `data/config.json`, поле `rename_vote_need`).
  Если за **120 секунд** голосов не хватило — попытка отклоняется, можно начать заново.
- **Защита от накрутки**: один компьютер — один голос за одно голосование; у каждого голосования уникальный номер.
- Заявка и результат попадают в общий журнал и видны всем.

### 3.8 Личные сообщения и секретная пересылка офлайн

**Как открыть**: аватар участника на вкладке «成员» либо аватар/имя в области чата.

**Если получатель в сети**: сообщение адресное — его видит только получатель, остальные ничего не видят, в журнал оно не попадает.

**Если получатель не в сети (секретная пересылка)** — всё происходит автоматически:

1. ваша программа **шифрует** сообщение случайным ключом (для каждого сообщения — новый ключ) и передаёт его участнику C, который сейчас в сети;
2. **C ничего не замечает**: нет окон, нет записей в журнале, в интерфейсе ничего не видно, на диске — только шифротекст;
3. как только получатель B появляется в сети (широковещательный «пульс»), программа C сама отправляет ему зашифрованный пакет напрямую;
4. B расшифровывает пакет и проверяет **HMAC-подпись целостности**; только при успехе отправляется подтверждение,
   после чего C **удаляет** у себя сохранённое; при ошибке проверки данные остаются и повторяется попытка (до 3 раз);
5. у B сообщение выглядит как обычное личное сообщение с пометкой «离线转存送达» (доставлено из офлайн-хранилища).

> Примечание: используется потоковый шифр из стандартной библиотеки + HMAC — это «машинный» уровень секретности
> (пользователь компьютера-хранителя не может посмотреть сообщение в приложении). Для защиты от чтения файлов
> на диске хранителя потребовалось бы асимметричное шифрование.

### 3.9 Как распространяются файлы

1. **Отправитель в сети** → получатель качает файл **напрямую** у отправителя (проверка SHA-256, при повреждении — повтор).
2. **Отправитель не в сети** → в «Журнале» публичный запрос (виден всем, но выполнить его может только программа):
   компьютеры, у которых файл уже есть, автоматически сообщают свой IP; запрашивающий берёт файл у **первого ответившего**.
3. При входе в группу список файлов синхронизируется автоматически — пропущенные файлы докачиваются.

### 3.10 История активности в локальной сети (новое)

Программа сохраняет происходящее в локальной сети (общий журнал, групповой чат, операции прокси, системные
сообщения и напоминания о появлении в сети) в **историю активности** на этом компьютере (`data/active_log.json`)
и позволяет устройствам **дополнять данные друг друга** — пропущенное за время выключения или отключения не теряется.

- **Подсказка при запуске «пустого» устройства**: если у программы ещё нет никаких данных о локальной сети (нет внутренней сети, нет истории активности и нет ни одной группы), при запуске появляется окно с заголовком `内部网` и текстом **«当前没有局域网网络活动，是否新建？»**; кнопки — **`是，新建（推荐）`** и **`否，稍后`**: «да» → создаётся внутренняя сеть и открывается создание группы, «нет» → в журнал пишется только строка «当前没有局域网网络活动（未新建）». Если данные уже есть, окно **не показывается** — вместо этого работает автодополнение ниже.
- **Автодополнение при запуске**: при старте (и далее раз в 60 секунд) устройство рассылает свой **физический адрес + IP + время последнего получения данных**, число событий и время начала непрерывной работы; остальные устройства внутренней сети **сразу отвечают проверочными данными** (адрес, время непрерывной работы, время последних данных, число событий и контрольный отпечаток), и каждая такая строка попадает в журнал.
- **Выбор источника**: в течение **6 секунд** запрашивающий отбирает ответы, у которых устройство «работает непрерывно ещё с момента до моего последнего получения данных», и берёт **ответившее раньше всех**; затем по TCP забирает пропущенные события и объединяет их. Если ответов нет — в журнал пишется, что нет устройства, пригодного для дополнения истории активности.
- **Пример**: устройство 1 выключилось в **22:00**, устройство 2 работало **всю ночь**; утром устройство 1 видит, что устройство 2 работает с момента до 22:00 и ответило быстрее всех, и **дополняет всю активность с 22:00 до момента включения**. После этого устройство 1 само становится источником и **при следующем появлении других устройств отдаёт данные им**.
- **Правила объединения**: события дедуплицируются по уникальному идентификатору, сортируются по времени, хранится не более **5000** записей (самые старые отбрасываются). Вверху страницы журнала есть строка состояния: `局域网活动：最后一次数据获取时间 10-10 08:00:00 · 活动记录 128 条`.

### 3.11 Прокси передачи данных (новое)

Если при отправке файла или сообщения в группу **никого из участников нет в сети**, программа **временно размещает**
содержимое на других онлайн-устройствах локальной сети — это и есть «прокси передачи данных».

- **Запрос и ответы**: когда в группе никого нет в сети, программа рассылает всем онлайн-устройствам локальной сети запрос на временное хранение; в журнале видны строки о том, кто инициировал запрос, кто ответил «в сети» и кому был отправлен прокси (например, «已向「设备二」发送文件代理「作业.txt」（临时寄存，用户不可查看）»). Если никто не ответил — в журнал пишется, что в локальной сети нет других онлайн-участников и прокси не создан (файл остаётся на этом компьютере).
- **Форма хранения**: файлы прокси всегда имеют суффикс **`.proxy`** (`data/proxy/<id>.proxy`, исходное имя хранится только в метаданных); в интерфейсе они **не видны, не открываются и не попадают в списки**, отражаются только в журнале; в прокси участвуют только участники внутренней сети.
- **Доставка и удаление**: как только нужный участник появляется в сети (сначала пишется напоминание о его появлении), устройство с прокси автоматически доставляет содержимое и **удаляет локальную копию**; если участник группы **долго не появляется**, копия **дополнительно рассылается** другим устройствам локальной сети (локальная копия сохраняется).
- **Очистка после принятия**: когда содержимое принято адресатом, рассылается сообщение «прокси принят», и **все устройства, когда-либо хранившие его, автоматически удаляют** копию; то же удаление выполняется и при **дополнении истории активности** от других устройств, поэтому мусор не остаётся.

### 3.12 Версии и обновление

**Обновление выполняют две отдельные программы**: основная программа `neiwang.py` / `neiwang.exe` только проверяет
наличие новой версии и показывает окно, а само обновление делают лежащие в той же папке
**обновлятор 1 `neiwang_update1.py`** (в версии на C++ — `neiwang_update1.exe`) и
**обновлятор 2 `neiwang_update2.py`** (в версии на C++ — `neiwang_update2.exe`).
Прежняя единая программа `neiwang_update.py` удалена, а `更新.bat` теперь запускает **обновлятор 1**.

**Файл-манифест `update.wenyi`** (лежит рядом с программой; копия публикуется на GitHub / вашем сайте):

```
2.0.0
- Полностью новая версия на C++ (чистый Win32 + GDI+, без сторонних зависимостей); протокол полностью совместим с Python-версией, обе работают в одной сети
- Новая «история активности в локальной сети»: при запуске рассылаются физический адрес, IP и время последнего получения данных, а пробелы дополняет устройство, работающее непрерывно дольше всех
- Новый «прокси передачи данных»: если в группе никого нет в сети, файл или сообщение временно размещается на онлайн-устройствах локальной сети, а затем доставляется и удаляется
- Новая подсказка при запуске «пустого» устройства: «当前没有局域网网络活动，是否新建？»
- Обновление разделено на две программы: обновлятор 1 обновляет всё, кроме себя, обновлятор 2 обновляет сам обновлятор 1
- Сохранены все возможности v1.1: приём в сеть и голосование, чат, личные сообщения, секретная пересылка офлайн, файлы группы с офлайн-поиском, голосование за имя, общий журнал
```

- **Первая строка — номер версии**, остальные строки — список изменений (можно и в формате JSON: `{"version": "2.0.0", "notes": ["..."]}`).
- **Версия самой программы тоже берётся из первой строки локального `update.wenyi`** — при выпуске новой версии правится один файл.
- **Основная программа `neiwang.py` проверяет обновления при каждом запуске**, но беспокоит вас только тогда,
  когда обновление действительно есть: **нет сети или удалённая версия совпадает с локальной (или старее)
  → полная тишина, никаких окон**; окно появляется только при **обновлении** (удалённая версия новее):

```
新版本 —— v2.0.1

更新内容：
- 修复了 xxx
- 新增了 yyy

（当前版本 v2.0.0）

«是» — запустить обновлятор 1 и обновиться сразу: он скачает новую версию,
все ваши данные переписки сохранятся (папка customer_god) и будут перенесены;
«否» — открыть страницу публикации; «取消» — позже.
```

**Параметры командной строки (одинаковые у обеих программ обновления):**

| Параметр | Действие |
| --- | --- |
| (без параметров) | ручной режим, всегда даёт понятный ответ (уже последняя версия / не удалось подключиться к серверу обновлений / найдена новая версия и показано окно) |
| `--auto` | автоматический режим, молча: окно только при наличии новой версии |
| `--update` | без вопросов сразу начинает обновление (именно так вызывает её основная программа при нажатии «是») |
| `--check` | проверка без интерфейса, печатает одну строку: `UPDATE_AVAILABLE версия` / `UP_TO_DATE версия` / `OFFLINE` |
| `--patch-updater1` | **только у обновлятора 2**: без проверки и загрузки просто копирует обновлятор 1 из `update_clone/` в папку программы |
| `--wait-pid <pid>` | ждёт завершения указанного процесса (обновлятор 1 передаёт так свой pid обновлятору 2; в версии на C++ тайм-аут 30 секунд) |
| `--root <path>` | задаёт рабочий каталог обновления (параметр версии на C++; в Python-версии используется переменная окружения `NEIWANG_UPDATE_ROOT`) |

**Три шага обновления (выполняет обновлятор 1):**

1. текущая папка `data/` (**все данные пользователя**: группы, переписка, индекс файлов, хранилище)
   целиком копируется в новую папку **`customer_god/`** рядом с программой;
2. новая версия помещается в папку **`update_clone/`**: если установлен Git и задан `update_repo`,
   используется `git clone --depth 1` (неглубокое клонирование); иначе **ZIP-пакет обновления просто
   скачивается и распаковывается** — устанавливать Git не нужно, это удобно для локальной сети;
3. содержимое `customer_god/` **возвращается** в папку `update_clone/data/` новой версии.

**Четвёртый шаг обновлятора 1: обновление «всего, кроме себя», на месте**:

4. файлы из `update_clone/` копируются в папку программы с сохранением относительных путей, но **пропускаются**
   `data/` (данные пользователя не трогаются), `customer_god/`, `update_clone/` и **сам обновлятор 1**;
   удаляются старые «программные» файлы, которых больше нет в `update_clone/` (`*.py`, `*.exe`, `*.bat`,
   `update.wenyi`, `README.md`, `*.md` кроме `docs/`);
5. записывается `.update_manifest_applied` (версия + время), в `update_clone.log` добавляется строка.

**Пятый шаг: обновлятор 2 обновляет сам обновлятор 1**:

- завершив обновление на месте, обновлятор 1 запускает **обновлятор 2** с параметрами
  **`--patch-updater1 --wait-pid <pid>`** (берётся версия из `update_clone/`, иначе из папки программы);
- обновлятор 2 **делает только одно**: копирует обновлятор 1 из `update_clone/` в папку программы.
  В Windows запущенный exe нельзя перезаписать, поэтому обновлятор 2 сначала ждёт завершения обновлятора 1
  (тайм-аут 30 секунд); если не получилось — новый файл сохраняется как `neiwang_update1.new.exe` с предложением перезапуска;
- по завершении в журнал пишется «обновлятор 1 обновлён обновлятором 2 до версии v…».

После этого показывается путь к новой версии: можно одной кнопкой открыть папку новой версии или
запустить её (`启动.bat`) — переписка и файлы сохранятся. При ошибке будет указана причина
(нет Git и не задан `update_package`, не задан адрес репозитория, нет доступа к сети и т. п.).

### 3.14 Частые вопросы

- **Компьютеры не видят друг друга?** Проверьте, что они в одной подсети; разрешите Python в брандмауэре; убедитесь, что на роутере не включена изоляция клиентов.
- **Порт занят?** Программа автоматически пробует порты после 45431; UDP 45455 используется только для поиска.
- **Можно ли скачать файл, если отправитель выключил компьютер?** Да — если файл есть у кого-то из участников в сети.
- **Удаляются ли файлы при выходе из группы?** Нет, скачанные файлы остаются на компьютере.
- **Имя не меняется?** Значит, вы уже меняли его один раз — нужно больше 5 голосов «за»; при малом числе участников уменьшите `rename_vote_need` в `config.json`.
- **Потеряется ли личное сообщение, если получатель не в сети?** Нет — оно шифруется и хранится у участника в сети, а затем доставляется автоматически.
- **Работают ли версия на C++ и Python-версия вместе?** Да. Протокол полностью совместим: обе версии видят друг друга в одной внутренней сети и одной группе, структура `data/` тоже одинаковая.
- **Увижу ли я сообщения, отправленные пока компьютер был выключен?** Да — история активности при запуске рассылается по сети, и устройство, работающее непрерывно дольше всех, дополняет пропущенный период.
- **Что за файлы `.proxy` в журнале?** Это временное хранилище «прокси передачи данных» (используется, когда в группе никого нет в сети); в интерфейсе они не видны и не открываются, а после доставки удаляются.
- **Обновление не сработало?** Смотрите причину, которую выдала программа: ① при обновлении через Git — установлен ли Git (`git --version`) и задано ли поле `update_repo`; ② если Git не установлен — задайте в `data/config.json` адрес ZIP-пакета `update_package`; ③ если всё в порядке — проверьте доступ к серверу обновлений / репозиторию; ④ если появился файл `neiwang_update1.new.exe`, значит обновлятор 1 ещё работал — просто перезапустите программу.
- **Как корректно закрыть программу?** Просто закройте окно — всё сохраняется автоматически.

### 4.5 Intranet admission and join voting (new)

The app groups the computers on your LAN into an "**intranet**": **until you are admitted, the app is
empty** — groups, chat and files are all unavailable. Every computer's **physical address (MAC)** is
recorded in a shared member registry that is synchronised across the whole network.

**What happens at startup**: if you are already in a network, you announce it; otherwise the app first
**scans** for nearby networks — if one is found it **applies to join** automatically; if none is found it
**creates its own** (you become the founder).

**Voting thresholds**:

| Current members | What a newcomer needs |
| --- | --- |
| **≤ 5** | no vote, admitted automatically |
| **6–7** | **unanimous** approval |
| **≥ 8** | **more than 1/3** approvals (8 → 3 votes, 9 → 4, 12 → 5) |

**How voting works**: every join request is collected under the "**Vote**" icon on the left — a **red dot**
appears, and the panel opens **only when you hover the icon**. Choices: **approve / reject / abstain**.
The dot disappears once you vote; **you can change your vote within 5 minutes**; **a vote stays open for
1 day** and then counts as finished; the history lives under "**More**".
There is **no auto-approve setting** — a human always decides.

> Machines without a usable MAC (some virtual machines) get a persistent random ID shown as
> `RND-XXXX-XXXX-XXXX`; it is registered and votes just like a real address.

### 4.7 Rename voting rules

- **First rename**: saved directly in Settings, effective immediately, no approval needed.
- **Second and later**: clicking "保存名字" broadcasts a voting request; every other online user gets a
  dialog "X wants to change the name from A to B — do you agree?" with 同意 / 拒绝 buttons.
- **Passing condition**: **more than 5 approving votes** (default; change `rename_vote_need` in `data/config.json`).
  If not enough votes arrive within **120 seconds**, the request fails and can be started again.
- **Anti-cheating**: one computer counts once per vote, and each vote has a unique ID.
- Requests and results are written to the public log for everyone to see.

### 4.8 Private chat and offline secret relay

**How to open**: the "成员" (members) tab in a group, or any avatar/name inside the chat area.

**Recipient online**: the message is addressed, so only the recipient sees it — no UI, no log entry for anyone else.

**Recipient offline (secret relay)** — fully automatic:

1. your app **encrypts** the message with a random key (a fresh key per message) and hands it to an online classmate C;
2. **C notices nothing**: no popup, no log, nothing in the UI — only ciphertext on disk;
3. as soon as recipient B comes online (heartbeat broadcast), C's program sends the encrypted packet directly to B;
4. B decrypts it and verifies the **HMAC integrity signature**; only on success does it acknowledge, and C then
   **deletes** the stored copy. If verification fails, the packet is kept and retried (up to 3 times);
5. on B's side the message looks like a normal private message, tagged "离线转存送达" (delivered from offline relay).

> Note: the relay uses a standard-library stream cipher plus HMAC — "machine-level" secrecy and integrity checking
> (the relay user cannot view it in the app). Resisting a relay owner who inspects raw disk files would require
> asymmetric encryption.

### 4.9 How group files are distributed

1. **Sender online** → the receiver downloads **directly** from the sender (SHA-256 verified, retried on corruption).
2. **Sender offline** → a **public request** is posted in the log (everyone can read it, only programs act on it):
   peers that already have the file answer with their LAN IP, and the requester takes the file from the
   **first responder** — no user interaction needed on either side.
3. Joining a group syncs that group's file list, so previously missed files are downloaded automatically.

### 4.10 LAN activity history (new)

The app persists everything that happened on the LAN (public log lines, group chat, proxy operations, system and
online notices) as a local **LAN activity history** (`data/active_log.json`) and lets devices **fill in each other's
gaps** — information missed while powered off or offline is not lost.

- **Empty-device prompt**: if the program has no LAN-related data at all (not in an intranet, no activity history, no groups), a dialog appears at startup titled `内部网` with the text **"当前没有局域网网络活动，是否新建？"** and the buttons **`是，新建（推荐）`** / **`否，稍后`**; "yes" creates an intranet and opens the new-group dialog, "no" only writes the log line "当前没有局域网网络活动（未新建）". When data already exists the dialog is **not shown** and the automatic fill-in below runs instead.
- **Automatic fill-in at startup**: at startup (and every 60 seconds afterwards) the device broadcasts its **physical address + IP + last data-fetch time**, its event count and how long the current process has been running; other intranet members **reply immediately with validation data** (address, run start, last data time, count and a checksum fingerprint), and each reply is written to the log.
- **Choosing a source**: within a **6-second** window the requester keeps the replies whose device "has been running continuously since before my last data-fetch time" and picks the **fastest responder**; it then pulls the missing events over TCP and merges them. If nothing answers, the log records that no device can supply the missing activity data.
- **Example**: device 1 shuts down at **22:00** while device 2 stays online **all night**; the next morning device 1 sees that device 2 has been running since before 22:00 and answered first, so it **fills in all activity from 22:00 until boot**. Device 1 then becomes a source itself and **serves that data to others when they come online**.
- **Merge rules**: events are de-duplicated by unique ID, sorted by time, capped at **5000** entries (oldest dropped). A status line sits at the top of the log page: `局域网活动：最后一次数据获取时间 10-10 08:00:00 · 活动记录 128 条`.

### 4.11 Device data-transfer proxy (new)

When you send a file or a message to a group and **nobody else in that group is online**, the app **parks the
content temporarily on other online LAN devices** — this is the "device data-transfer proxy".

- **Request and replies**: with nobody online in the group, the app asks every online LAN member to hold the content temporarily; the log shows who raised the request, who replied that they are online, and whom the proxy was sent to (for example "已向「设备二」发送文件代理「作业.txt」（临时寄存，用户不可查看）"). If nobody replies, the log records that no other online member can hold it and no proxy was created (the file stays on this computer).
- **Storage form**: proxy files always end in **`.proxy`** (`data/proxy/<id>.proxy`, the original name is kept only in the metadata); they are **invisible in the UI, cannot be opened and never appear in any list** — only the log mentions them. Only intranet members take part in proxying.
- **Delivery and cleanup**: as soon as the relevant member comes online (an online notice is logged first), the holding device delivers the content automatically and **deletes its local copy**; if the group member **stays offline** past the configured window, a copy is **spread to other LAN devices** (the local copy is kept).
- **Cleanup after acceptance**: once the content is accepted, the app announces that the proxy was consumed, and **every device that ever stored it deletes its copy**; the same deletion is performed when a device **catches up on activity history** from others later, so nothing is left behind.

### 4.12 Versioning and updates

**Updating uses two separate programs**: the main program `neiwang.py` / `neiwang.exe` only checks and shows a
dialog, while the actual update is performed by **updater 1 `neiwang_update1.py`** (C++: `neiwang_update1.exe`) and
**updater 2 `neiwang_update2.py`** (C++: `neiwang_update2.exe`) in the same folder.
The old single updater `neiwang_update.py` has been removed; double-clicking `更新.bat` now starts **updater 1**.

**Manifest file `update.wenyi`** (shipped next to the program; a copy is published on GitHub / your website):

```
2.0.0
- Brand-new native C++ build (pure Win32 + GDI+, zero third-party dependencies); fully protocol-compatible with the Python build and able to share one network with it
- New "LAN activity history": broadcasts physical address / IP / last data-fetch time at startup and fills gaps from the device that has been running continuously the longest
- New "device data-transfer proxy": files or messages are parked on online LAN devices while nobody in the group is online, then delivered and reclaimed automatically
- New empty-device startup prompt "当前没有局域网网络活动，是否新建？"
- Updates split into two updaters: updater 1 refreshes everything except itself, updater 2 refreshes updater 1
- All v1.1 features kept: intranet admission and join voting, group chat, private chat, offline secret relay, group files with offline fallback, rename voting, public log
```

- **Line 1 is the version number**; the remaining lines are the changelog (JSON is also supported:
  `{"version": "2.0.0", "notes": ["..."]}`).
- **The app's own version also comes from line 1 of the local `update.wenyi`** — releasing a new version means
  editing just this one file.
- **The main program `neiwang.py` checks for updates on every startup**, but it only bothers you when an update
  really exists: **no network, or a remote version equal to (or older than) the local one → completely silent,
  no window at all**; a dialog appears only for an **update** (remote version is newer):

```
新版本 —— v2.0.1

更新内容：
- 修复了 xxx
- 新增了 yyy

（当前版本 v2.0.0）

"Yes" — launch updater 1 and update immediately: it fetches the new version and
all your session data is saved into the customer_god folder and carried over;
"No" — open the release page; "Cancel" — later.
```

**Command-line options (identical for both updaters):**

| Option | Behaviour |
| --- | --- |
| (none) | manual mode — always gives a clear answer (already up to date / cannot reach the update server / a new version was found and a dialog is shown) |
| `--auto` | automatic mode, silent — a dialog appears only when a new version exists |
| `--update` | no questions asked, starts updating immediately (this is how the main program invokes it when you click "Yes") |
| `--check` | headless check that prints exactly one line: `UPDATE_AVAILABLE <version>` / `UP_TO_DATE <version>` / `OFFLINE` |
| `--patch-updater1` | **updater 2 only**: skips checking and downloading and simply copies updater 1 from `update_clone/` into the program folder |
| `--wait-pid <pid>` | waits for the given process to exit (updater 1 passes its pid to updater 2; the C++ build times out after 30 seconds) |
| `--root <path>` | sets the update working directory (C++ build option; the Python build uses the `NEIWANG_UPDATE_ROOT` environment variable) |

**The three update steps (performed by updater 1):**

1. the current `data/` folder (**all of the user's session content**: groups, chats, file index, relay store)
   is backed up into a new folder **`customer_god/`** next to the program;
2. the new version is fetched into **`update_clone/`**: when Git is installed and `update_repo` is configured,
   a shallow `git clone --depth 1` is used; otherwise the **ZIP update package is downloaded and unpacked
   directly** — no Git installation required, which suits intranet deployments;
3. the content of `customer_god/` is **restored** into the new version's `update_clone/data/` folder.

**Updater 1's fourth step: in-place refresh of "everything except itself"**:

4. files from `update_clone/` are copied over the program folder keeping their relative paths, but `data/`
   (your own data is left alone), `customer_god/`, `update_clone/` and **updater 1 itself** are **skipped**;
   old program files no longer present in `update_clone/` are deleted (`*.py`, `*.exe`, `*.bat`, `update.wenyi`,
   `README.md`, `*.md` outside `docs/`);
5. `.update_manifest_applied` (version + timestamp) is written and a line is appended to `update_clone.log`.

**Updater 2's fifth step: updater 2 refreshes updater 1 itself**:

- when the in-place refresh is done, updater 1 launches **updater 2** with
  **`--patch-updater1 --wait-pid <pid>`** (preferring the new copy in `update_clone/`, otherwise the one in the program folder);
- updater 2 **does exactly one thing**: it copies updater 1 from `update_clone/` into the program folder.
  A running exe cannot overwrite itself on Windows, so updater 2 first waits for updater 1 to exit (30-second timeout);
  if that still fails, the new file is written as `neiwang_update1.new.exe` with a prompt to restart;
- on success the log records "updater 1 has been updated to v… by updater 2".

The path of the new version is then shown, with one-click options to open the new version's folder or start it
(`启动.bat`) — your chats and files are intact. Failures report a concrete reason (Git missing and
`update_package` not configured, repository not configured, network unreachable, and so on).

**Settings (`data/config.json`)**:

| Field | Meaning |
| --- | --- |
| `update_url` | Manifest URL (already points to this repository's raw): `https://raw.githubusercontent.com/ZZZ-need-sleep/Local_Network_Communication-created-by-DeepDeek-/main/update.wenyi` |
| `update_page` | Release page opened by the "No" button (already points to this repository's home page: `https://github.com/ZZZ-need-sleep/Local_Network_Communication-created-by-DeepDeek-`) |
| `update_repo` | Repository used for Git-based updates: `https://github.com/ZZZ-need-sleep/Local_Network_Communication-created-by-DeepDeek-.git` |
| `update_package` | URL of the ZIP update package (e.g. `http://intranet-server/内部网.zip`); used for updates in intranet environments without Git |

> Note: `update_url` and `update_repo` already point to the repository above. If your default branch is `master` rather
> than `main`, change `main` in the code (or in `config.json`) to `master`.

### 4.13 Data directories

```
data/
├─ config.json          # settings: name, groups, ports, update URLs, rename-vote options
├─ net.json             # intranet: my network, member registry (MAC / IP / join time), join requests and my votes
├─ index.json           # file index (hash -> name / sender / group)

├─ proxy.json           # device data-transfer proxy metadata (id -> group / file name / targets / current holder)
├─ proxy/<id>.proxy     # proxy file bodies (suffix always .proxy; invisible in the UI and cannot be opened)
├─ cache/<hash>          # file content cache (also used to serve files to others)
├─ downloads/<group>_<id>/   # auto-downloaded files, one folder per group
├─ secret_relay.json    # offline private messages relayed for others (ciphertext + signature), deleted after delivery
└─ secret_received.json # IDs of relays already received (deduplication)

customer_god/           # backup of "all user session content" created by updater 1
update_clone/           # the new version fetched by updater 1, ready to be copied over the program folder (including data/)
update.wenyi            # version manifest: version number (currently 2.0.0) + changelog
update_clone.log        # update log (one line per step)
.update_manifest_applied # version and time of the last in-place update
_neiwang_update1.pid    # pid of updater 1 (used by updater 2 to wait for it)
```

> The `data/` layout is **identical** in the Python and C++ builds, so data can be moved between them.

### 4.14 FAQ

- **Two computers cannot see each other?** Make sure they are on the same subnet, allow Python through the
  firewall, and check that the router does not enable AP/client isolation.
- **Port already in use?** The program automatically tries ports after 45431; UDP 45455 is only used for discovery.
- **Can files still be downloaded after the sender shuts down?** Yes — as long as any classmate who already has
  the file is online, the file is fetched from them automatically.
- **Does leaving a group delete files?** No, downloaded files stay on your computer.
- **I cannot rename myself anymore?** You already renamed once; more than 5 classmates must approve. With few
  members, lower `rename_vote_need` in `config.json`.
- **Are private messages lost when the recipient is offline?** No — they are encrypted and parked on an online
  peer, then delivered automatically once the recipient appears.
- **Can the C++ build and the Python build be used together?** Yes. The protocol is fully compatible: both builds see each other on the same intranet and in the same group, and the `data/` layout is identical too.
- **Will I see messages sent while my computer was off?** Yes — the LAN activity history is broadcast at startup and the device that has been running continuously the longest fills in the period you missed.
- **What are the `.proxy` files in the log?** They are the temporary storage of the device data-transfer proxy (used only when nobody in the group is online); they are invisible in the UI, cannot be opened, and are deleted after delivery.
- **Update failed?** Follow the reason the program prints: ① for Git-based updates, check that Git is installed (`git --version`) and that `update_repo` is configured; ② if Git is not installed, set `update_package` (the ZIP update package URL) in `data/config.json`; ③ if all of that is fine, check that the update server / repository is reachable; ④ if a `neiwang_update1.new.exe` file appears, updater 1 was still running — just restart the program to finish the replacement.
- **How do I quit cleanly?** Just close the window — all state is saved automatically.
